# TurboVision JS — API Documentation

This document describes the current public object model and module layout.
Implementation history and user-visible changes are recorded in `CHANGELOG.md`.

THelpViewer uses a modular JavaScript framework inspired by Borland's TurboVision TUI toolkit. The runtime assets are served from `www/assets/`:

| File | Purpose |
|------|---------|
| `tv-core.js` | Core widget classes, dialog manager, theme engine, utility functions |
| `tv-context-help.js` | Shared UHF `TVHelpWindow`/`TVHelpViewer`, THelpViewer's UHF loader and generated-page context help |
| `tv-dialogs.js` | Standard dialogs including Server Statistics |
| `tv-games.js` | Game dialogs and rules (Puzzle, Tetris, Minesweeper, BreakOut, Sokoban, Lines, Reversi, Ludo, Mastermind, Snake, Tron, Tower of Hanoi) |
| `tv-dos.js` | `TVDosWindow` (shared `TVWindow` chrome) and `TVDosView` (DOSBox canvas, TVEvent input, audio and cloud file synchronization) |
| `tv-screensaver.js` | Screen saver base class and animated modes |
| `tv-highlight.js` | Pascal, C and ASM syntax highlighting |
| `tv-shell.js` | Menu bar, status line, window resizer, application bootstrap |
| `tv-bundle-app.js` | Single-page bundle viewer (catalog, window manager, Markdown renderer) |

All modules share a single namespace: `window.THelpViewerTV` (aliased as `TV`).
The syntax highlighter detects Pascal, C and ASM independently for each
contiguous code block, so one topic can safely contain examples in several
languages.

## tv-core.js

Core widget hierarchy and infrastructure.

### Widget Base Classes

- **TVView** — Base for all UI components. `constructor(bounds=TVRect())`,
  following `TView(const TRect&)`. `bindRoot()` is the private browser binding
  step and is not part of view construction. Drawing options and generated
  browser attributes are owned by the view itself; there is no separate
  renderer object or parallel renderer state.
  Stable browser identities are generated by the concrete drawing code, never
  mutable constructor arguments or caller-set instance fields. A specialised
  subclass is retained only when it adds TVision behaviour or genuinely
  distinct drawing; status-only Search and Find text use `TVStaticText`
  directly.
  `setHelpCtx()` and `getHelpCtx()` attach or resolve a Turbo Vision-style
  context identifier.
- **TVRect** — Character-cell bounds used by windows and dialogs. It mirrors
  Turbo Vision's `(x1, y1, x2, y2)` rectangle convention.
- **TVStaticText** — `constructor(bounds, text)`. `getText()`, `setText()` and
  `draw()` mirror the basic `TStaticText` contract.
- **TVImage** — `constructor(bounds)`, `setImage(src, alt)`. A shared bounded
  view for optional bitmap art; bounds still use `TVRect` character cells.
  The MIDI Player uses it for source-provided game/soundtrack cover images.
- **TVLabel** — `constructor(bounds, text, link)`. The third argument is the
  target `TVInputLine` object; the browser renderer creates any native id/for
  pair internally. As in DOS Navigator's `TLabel`, `~F~` marks a mnemonic:
  Alt+F focuses the linked view through the owner event chain; clicking the
  label also focuses it.
- **TVInputLine** — `constructor(bounds, maxLen)`, plus `getData()`,
  `setData()`, `setValidator()` and disabled-state handling. It accepts no DOM
  id, attributes, class or style. `TVPXPictureValidator` implements the fixed
  `!` (uppercase character) and literal-separator subset of Turbo Vision's
  picture validator; registration tokens use five groups of five characters.
- **TVGroup** — `constructor(bounds)`. Children are added with `insert()` or
  `insertAll()`; only `TVView` instances are accepted. `setCurrent(child)`
  makes `getHelpCtx()` inherit from the current child,
  matching the relevant part of `TGroup::getHelpCtx()`.
- **TVListViewer** — `constructor(bounds, numCols)`. Items and selection are
  supplied through `setItems()`/`select()`; its DOM root is attached later
  through `bindRoot()`.
- **TVListBox** — Interactive selectable list. `setItems(items, index)`,
  `select(index)`, `bind({onSelect, onActivate})`; click selects and
  double-click/Enter activates. It owns the shared scrollbar integration,
  row rendering and palette, roving tab focus,
  pointer-coordinate row selection, Arrow, Home/End and Page Up/Down keyboard
  navigation. `TVListViewer.handleEvent()` processes the browser bridge's
  `TVEvent` for these actions; `TVListBox` supplies its viewport-specific
  pointer and page movement without a second set of DOM handlers. Visibility
  is measured against the real viewport rectangle, so
  focus changes cannot introduce an offset between a drawn and clicked row.
  While its dialog is inactive, the scrollbar keeps its Turbo Vision palette
  but ignores input. Browser item classes, data hooks and row markup are
  private to concrete list subclasses, not caller-set `TVListBox` options.
  When a view owns an `hScrollBar`, an overlong row reveals the shared bottom
  scrollbar and can be moved horizontally; short rows leave it hidden.
- **TVGridView** — Read-only two-dimensional `TVListBox` subclass.
  `TVGridView(bounds, columns, hScrollBar, vScrollBar)` takes column titles and
  optional character widths; `setRows()` accepts arrays of cell values.
  Headers are visible by default and `setHeadersVisible()` toggles them.
  Click or Left/Right/Up/Down selects a cell, while the inherited shared
  scrollbars move the viewport in both directions. Grid Viewer in the system
  menu exercises the control; cells are not edited in this first version.
- **TVOutline** — Tree-oriented `TVListBox` with shared selection,
  scrolling and activation plus expand/collapse state and Left/Right keyboard
  navigation in `handleEvent()`. HELP Contents and Change Directory both use it.
- **TVScroller** — `TVScroller(bounds, hScrollBar, vScrollBar)` keeps the
  original scroller/scrollbar ownership split and exposes `delta` and `limit`.
- **TVMenu** / **TVMenuItem** — Source-shaped menu and command records. A
  `TVMenu` owns the head of a linked `TVMenuItem.next` list plus `deflt`;
  neither object exposes browser markup options. `NewItem()`, `NewMenu()`,
  `NewLine()` and `NewSubMenu()` mirror the Pascal construction helpers.
- **TVSubMenu** — `TVMenuItem` subclass which owns its nested `TVMenu`, matching
  the C++ Turbo Vision hierarchy.
- **TVMenuView** — Owns the menu, current selection and popup state. Its
  one-time `bindRoot()` maps rendered buttons back to `TVMenuItem`; `refresh()`
  retains toggle, popup and item elements for navigation instead of querying
  them again on each event.
  `handleEvent()` processes `evMouseDown`, `evMouseMove` and `evKeyDown`, then
  sends the selected item's `evCommand` through the view owner to the app.
  `~mnemonic~` text is translated only while drawing.
- **TVMenuBar** — Shared top-level `TVMenuView`; generated pages and the bundle
  application now compose the same object tree instead of assembling menu
  HTML.
- **TVMenuBox** — `TVMenuView` popup subclass constructed from bounds, a
  `TVMenu` and an optional parent menu.
- **TVMenuController** — Browser boundary only: translates DOM click, hover
  and key events into `TVEvent` for the bound menu view. Status-line commands
  retain their separate command bridge.
- **TVCheckBoxes** — Native checkbox group rendered with DOS `[ ]` / `[X]`
  marks; supports click, Space, focus and disabled state.
- **TVRadioButtons** — Native mutually exclusive radio group rendered with DOS
  `( )` / `(·)` marks. The renderer generates the native browser group name;
  it is not part of the public constructor.
- **TVMultiCheckBoxes** — `TVCluster` subclass with configurable three-state
  DOS marks, keyboard-focusable buttons, disabled state and `aria-checked`.
- **TVTerminal** — Bounded append-only line buffer. `append(text)`, `clear()`
  and `bind(root)` update a fixed set of framed terminal rows. `appendChunk()`
  retains incomplete trailing lines when process output arrives in pieces.
  Its `TVRect`
  width includes both `TVInfoBox` side characters, so the right border cannot
  be painted outside and clipped by the owning view.
- **TVEditor** and **TVIndicator** — `TVEditor(bounds, hScrollBar, vScrollBar,
  indicator, bufSize)` is a read-only document control with selection,
  `find()`, `findNext()`, cursor position reporting and explicit lifecycle.
  Markdown Docs windows instantiate this pair instead of using a styled
  viewport alone. The editor owns one click-to-`TVEvent` bridge for document
  links; the application resolves Markdown targets through its `onLink`
  callback, while other links continue through normal navigation. Docs windows
  retain their editor, and HELP windows retain a Find editor only after their
  first search; both are destroyed with their owning `TVWindow`.
- **TVScrollBar** — `TVScrollBar(bounds, options)` is the sole scrollbar view;
  `sbHorizontal`/`sbVertical` select its axis. It owns
  the original value/range/page-step/arrow-step state and the corresponding
  `setParams()`, `setRange()`, `setStep()` and `setValue()` operations.
  Windows, menus and list viewers bind it to their rendered frame; no second
  scrolling implementation exists. Binding treats that frame as a browser
  host and does not replace its logical `_tvView`, so keyboard/command events
  continue through the owning list or scroller.
- **TVWindow** / **TVDesktop** — Bounds-first groups. `TVWindow` receives title
  and number; browser roots are attached with `bindRoot()` after construction.
- **TVButton** — Dialog command button. Like Turbo Vision's `TButton`, it is
  constructed as `TVButton(bounds, title, command, flags)` and identified by
  its title, command and `bfNormal`/`bfDefault`/`bfLeftJust`/
  `bfBroadcast` flags; `draw()`, `press()`,
  `makeDefault()` and `setState()` provide the basic control operations. It no
  longer represents menus or status-line items and has no `buttonKind`. Its
  shared minimum width is the original ten character cells; individual
  dialogs express wider buttons through their `TVRect`. `press()` dispatches
  its command through the owner chain; Enter on a dialog's default button does
  not synthesize a browser click. Its base `_drawParts()` now draws only the
  generic dialog button; specialized faces belong to the concrete ASCII,
  calendar, color, MIDI, search-result and game controls.
- **TVEvent** — Turbo Vision-style event record with `what`, `command`,
  `infoPtr`, `infoLong` and the private browser-event bridge.
  `TVButton.handleEvent()`
  changes `evMouseDown` into `evCommand`; `TVView.dispatchEvent()` propagates
  the event through `owner` until `clearEvent()` changes it to `evNothing`.
- **TVPercentGauge** / **TVBarGauge** — progress views modelled on DOS
  Navigator `GAUGE.PAS`. They receive `cmUpdateGauge`, `cmResetGauge` and
  `cmAddGauge` as `evBroadcast` events. `TVGroup.broadcast()` distributes
  these commands through owned groups, so dialogs do not manipulate gauge DOM
  or duplicate progress rendering. `TVBarGauge` draws a fixed-width `░` track
  that fills with solid `█` cells, and is shared by global indexing, HELP
  loading and MIDI playback.
- **TVMenuItem** / **TVStatusItem** — Command descriptors drawn by
  `TVMenuView`/`TVMenuBox` and the status line, matching Turbo Vision's
  separation between `TButton`, `TMenuItem` and `TStatusItem`.
- **TVStatusDef** / **TVStatusLine** — Context-range definitions created with
  `NewStatusDef()` and command records created with `NewStatusKey()`; the
  status line selects records through `findItems(helpCtx)`.
- Original Turbo Vision calls the virtual `TStatusLine.Hint(HelpCtx)` after the
  visible status commands, but its base implementation returns an empty
  string. DOS Navigator does not override it. THelpViewer's contextual sentence
  in that space is therefore a deliberate application extension, not default
  Turbo Vision menu behaviour.
- **TVMessageBox** — Modal Promise-based `TVDialog` composed from
  `TVStaticText` and `TVButton`, with OK/Cancel and
  Yes/No/Cancel flag combinations, mnemonics and default-button keyboard
  handling. Its text rows and command buttons are owned TVision children; it
  no longer replaces group contents with handwritten button HTML. The sizing
  follows DOS Navigator `MESSAGES.PAS`: at least 42×7 cells, a standard
  `TVDialog` close control, ten-cell buttons and two-cell button gaps. The close
  control and Escape resolve to Cancel when available, otherwise No for a
  Yes/No prompt; they never return the default affirmative command.

Dialogs are constructed without a desktop or DOM-root argument. The
application inserts them into `TVDesktop`; registering a dialog with
`TVDialogManager` performs the insertion automatically. `TVDesktop.insert()`
sets the Turbo Vision owner chain and mounts the already drawn root. This is
why constructors never query `.tv-desktop` and never fall back to
`document.body`.

Game windows follow the same composition rule: frames, buttons, labels,
lists, status/info boxes and Hall of Fame are shared TVision views. Only the
dynamically changing playfield is currently allowed to use game-specific
markup.

### TVInfoBox

Reusable framed info-box borders (used for game info panels).

Static methods:
- `TVInfoBox.header(width, title)` → `"┌── Title ──┐"`
- `TVInfoBox.footer(width)` → `"└───────────┘"`
- `TVInfoBox.separator(width, title)` → `"├── Title ──┤"`
- `TVInfoBox.rowHtml(width, content, borderClass)` → `"│ content    │"` (as HTML with styled border span)
- `TVInfoBox.applyBorders(width, specs)` — Batch apply header/footer/separator to DOM elements.

Header, footer and both row-side glyphs inherit the same current frame color.
When an info box contains bounded children, its header and footer remain fixed
to the first and last `TVRect` rows; positioned terminals therefore cannot
remove the bottom border or push it directly below the title.

### TVFrame, TVWindow & TVDialog

The built-in UHF Help Contents/Index includes Account/Login, registration and
tokens, Server Configuration/local rebuilds, DOS Prompt, Grid Viewer and Server
Terminal. Their concrete view constructors own hc2280–hc2340; corresponding
account/DOS menu items also carry these contexts. F1 in DOS keyboard input goes
to the emulator; F1 on its menu opens the native DOS Prompt help topic. Rebuild
confirmation and progress use shared TVMessageBox/TVIndexProgressDialog objects,
with all commands handled through TVEvent and no dialog-specific HTML/CSS.

- **TVFrame** — Generates dialog window markup (titlebar, body, footer, borders).
  Its active frame uses the Turbo Vision 2.0 double-line glyphs; the passive
  frame uses single-line glyphs. An inactive dialog keeps its close control
  visible and clickable in passive colors; standard windows retain their
  clickable Close control but substitute a frame segment for Zoom. The visible
  passive dialog icon is an intentional local
  exception to the original Turbo Vision 2.0 frame, which draws no icons in
  inactive windows. The close control
  is overlaid at columns 2–4 and the title is centered over one continuous
  frame line, matching `TFrame` rather than participating in the layout.
  `drawTitleControl()` / `createTitleControl()` are the single renderer for
  bracketed title controls: brackets inherit the title color while the inner
  glyph uses the owner's frame-icon color. Dialog close, History close and the
  games' Hall of Fame `[H]` use this path.
- **TVWindow** — Shared `TVGroup` base and standard window-frame composition
  used by HELP, Docs and dialogs. On a passive standard window, the Close
  control remains clickable and Zoom becomes a single-line frame segment.
  This preserves the centered caption and both
  frame corners while matching the inactive `TFrame` drawing.
  Windows without an outer scrollbar update both vertical frame sides, not
  only the left side. The shared browser mover caches drag limits at mouse-down
  and coalesces position writes with `requestAnimationFrame`; mouse-up flushes
  the final position before persistence, and destruction cancels queued work.
  Move/resize frame transitions use `updateWindowFrameState`, including the
  bottom border and restoration of the window's actual active/passive state.
  Standard close/zoom controls are semantic buttons. The close glyph changes
  to an asterisk while the mouse button is held, and the window closes only
  when the button is released over the control. Releasing elsewhere leaves the
  window open; keyboard activation also uses the native click event. If Safari
  omits the mouse-generated click, the shared close binder dispatches one
  fallback click after release. A
  double-click on the title row sends the same Zoom command as the top-right
  control. The grow
  control always draws Turbo Vision 2.0's source-
  defined single-line `─┘` icon. Generated standalone pages bind a `TVWindow`
  to their existing frame, so their anchor-style Close control dispatches the
  same window command and then follows its original `index.html` destination.
- **TVDialog** — `TVWindow` subclass constructed from `TVRect` bounds, a title
  and semantic options/content; it may be modal or non-modal. Callers do not
  provide CSS class names, close attributes or handwritten frame footers.
  - `open()`, `close()`, `destroy()`, `center()`, `isOpen()`, `isActive()`
  - `changeBounds(bounds)` / `locate(bounds)` — Change the Turbo Vision bounds
    and immediately redraw the affected character frame. Dynamic dialogs must
    use these instead of setting browser dimension variables directly.
  - `close()` hides a reusable dialog; `destroy()` permanently removes a
    dynamic dialog, its drag listeners and its manager registration.
  - `bindCommonClose(callback)` — Bind the common close action
  - Escape, menu Close/Cancel, title control and backdrop clicks converge on
    the `dialog-close` command in `handleEvent()`.
  - `bindDrag()` — Enable title bar drag. While moving, the shared frame uses
    the single-line Turbo Vision drag glyphs and restores its active/passive
    frame after mouse release.
  - `setManager(manager, name)` — Register with TVDialogManager
  - `focusableElements()` — Return the current keyboard focus cycle
  - `onDialogKeyDown(event)` — Shared Escape, default Enter and Tab handling
  - Native click, input, change and key-down events are translated once into
    `TVEvent` and propagated through the target view's owner chain.
    A shared key-up bridge exists only for controls that need held-key state;
    concrete dialogs do not install document-level keyboard listeners.
  - `_query(selector)` remains an internal renderer/composite helper; concrete
    dialogs do not use it to rediscover controls they created.
  - `setState(sfModal, ...)`, `keyboard` and `escapeCloses` customize shared
    interaction without duplicating document-level key handlers. Default Enter
    resolves the nested `TVButton` carrying `bfDefault` through the owner tree;
    there is no DOM selector option. The concrete dialog's static palette keeps
    identical active/passive/drag frame semantics.
  - `setHelpCtx()` writes the dialog-owned context to both its window and
    overlay roots. Application registration no longer maps names to contexts.

### Window behavior compared with Turbo Vision 2.0

Reference: [Borland Turbo Vision 2.0 Programming Guide](https://jexer.sourceforge.io/tvision/Turbo_Vision_Version_2.0_Programming_Guide_1992.pdf),
especially `TFrame` drawing/handling and `ofFirstClick` selection semantics.

| Behavior | Current browser implementation | Difference / next step |
|---|---|---|
| Active/passive frame | Double-line active and single-line passive frames | Inactive dialog `[■]` remains visible but disabled at the user's request; original `TFrame` omits inactive icons. |
| Frame commands | Close executes on mouse release; title-row double-click and zoom icon both send the window Zoom command | Browser click/double-click are translated to the existing `TVEvent` command path. |
| First click on an inactive window | `TVDialogManager` activates it on `mousedown` | `ofFirstClick` is defined but not yet enforced; a child control can still act on the activating click. Original windows normally only select on that first click. |
| Tab focus | `TVDialog` cycles browser-focusable elements | Original `TGroup` cycles selectable child views; reconcile these before replacing the DOM focus bridge, preserving native input focus and accessibility. |

The remaining first-click and focus differences are recorded here rather than
changed speculatively across every dialog in one pass.

### TVDialogManager

Manages dialog lifecycle, z-ordering, and active state.

- `register(name, dialog)` — Register a named dialog
- `unregister(name, dialog)` — Remove a dynamic dialog registration safely
- `registerWindow(name, element, commands)` — Register a managed window and
  its command handlers
- `setHostWindow(element, commands)` — Register the generated page's host
  window and its command handlers
- `open(name, {exclusive})` — Open a dialog (optionally closing others)
- `close(name)` — Close a dialog
- `bringToFront(name)` — Activate and focus a dialog
- `activateHostWindow()` — Deactivate all dialogs, activate host window
- `dispatchCommand(command)` — Send a command to the active dialog, viewer,
  document or host window
- `cycleTarget(delta)` — Activate the next or previous managed window/dialog
- `openTargets()` / `openWindowCount()` — Report currently usable managed targets
- `canDispatchCommand(command)` — Report whether the active target accepts a command
- `applyAllZIndices()` — Recalculate z-index stack
- `applyActiveStates()` — Update `is-window-active` / `is-window-inactive` classes
- `getHelpCtx()` — Return the active dialog/window/host context

URL-state restoration keeps every open modal dialog above ordinary windows
and makes the top modal active, even when an older serialized stack recorded
an invalid background position for it.

### Context Help

`TV_HELP_CONTEXTS` exports the application's `hc...` constants, including
`hcApplication`, menu contexts, HELP/Docs viewer contexts, individual
standard-dialog contexts and one context for each game. The constants are also
exposed directly on `THelpViewerTV` for Turbo Vision-style use.

- `elementHelpContext(element)` resolves `data-tv-help-ctx` through DOM owners.
- `TVMenuController.getHelpCtx()` returns the selected menu/root context.
- `resolveHelpContext()` prioritizes an open menu, focused view, active managed
  target and finally `hcApplication`.
- `TVHelpController` captures plain F1 and sends the resolved context to the
  application callback.
- Every concrete standard/game dialog passes its own `hc...` value to
  `TVDialog`; registration is deliberately context-agnostic.
- The bundle application loads `assets/tv-context-help.json`, a native UHF 2.0
  `THELPVIEWER.HLP` bundle, and passes the resolved `hc...` value directly to
  `BundleWindowManager.showTopic()`.
- `tv-context-help.json` contains a real alphabetical UHF index. Help > Index
  loads that bundle and passes it to `BundleWindowManager.showIndex()`; About
  is available only from the Help menu, not from the system menu.
- Every converted HELP file is owned by `TVHelpWindow : TVWindow` and its
  `TVHelpViewer : TVScroller`. THelpViewer Help therefore uses the same UHF
  renderer, right-edge `TVScrollBar`, frame controls, object lifecycle and
  URL-state path as every other converted HELP file. Back, Help Contents,
  Content, Search and Close stay in the global status line; no second
  navigation strip is rendered inside the window.
- The generated-page F1 path uses `TVContextHelpWindow : TVHelpWindow` rather
  than a parallel `TVDialog`. Its title frame, Close/Zoom controls, move/resize
  behavior, inactive palette and both outer scrollbars are produced by
  `TVWindow`; only topic markup and link handling are context-help-specific.
- Internal topic links, fixed-width tables and long text are handled by the
  existing UHF renderer. Restoring URL state reloads the same context bundle
  and selected topic.

The Help menu and `F1 Help` status command use the same context-resolution path
as the keyboard.

`TVMenuItem` follows the source constructor order `(name, command, keyCode,
helpCtx, param, next)`. `param` is the right-aligned accelerator label used by
Turbo Vision (for example `"F3"`), not an application payload. Commands carry
their application data outside the public TVision constructor. Disabled state
is changed on the retained `TVMenuItem`, rather than rediscovering a rendered
button with a DOM selector. `TVMenuView.handleEvent()` uses `TVEvent.infoPtr`
to identify the item, `TVMenuItem.subMenu` to distinguish submenus and the
linked menu to resolve keyboard shortcuts and mnemonics. The shared
`TVMenuController` only translates browser input into `TVEvent`; it does not
interpret the rendered button's `data-tv-command`. The status line follows
the same rule with retained `TVStatusItem` objects. Shortcuts activate the
same command path as mouse selection.

`TVCluster` keeps checkbox/radio selection and multi-check state in its
options and value. The DOM input or button is mapped to its option when the
view is resolved; `TVEvent.infoLong` reports that option to its owner. HELP
window view/topic/line/tag state is stored on `TVHelpWindow`, not the element's
dataset. URL restoration, context hints and menu availability read these
objects. Browser attributes remain for view-to-element binding, generated
page metadata, geometric measurement, accessibility and hit testing of
dynamic HELP links or game boards; they are not a second application state
model. `TVFrame` keeps the
command of each drawn title control; `TVWindow` and `TVDialog` dispatch that
command without reading a `data-tv-command` attribute back from the button.

### TVDesktop

Small `TVGroup` owner shared by the generated-page and bundle applications.

`TVProgram : TVGroup` is the common application-level owner. The generated
viewer's `TVApplication` and the catalog viewer's `TVBundleApp` both derive
from it; their constructors remain source-shaped and browser roots are bound
only during `start()`.
It owns the desktop root, one `TVDialogManager`, border/background layout,
clock updates and the global load/resize lifecycle. Product-specific startup
and navigation remain in `TVApplication` and `TVBundleApp`.

### TVMenuController

Browser event adapter used by both the generated-page shell and the bundle
viewer. Menu state and navigation belong to `TVMenuView`.

- `refresh()` — Discover the newly rendered `TVMenuView`
- `onCommand()` / `onHover()` / `onKeyDown()` — Convert browser events to
  `TVEvent` records carrying menu or status objects
- `destroy()` — Remove the controller's document-level listeners
- Supports `F10`, Alt mnemonics, popup mnemonics, arrows, `Home`, `End`,
  `Enter`, Space, Tab/Shift+Tab and `Esc`, including remembered selection and
  focus restoration. Disabled commands are skipped by mouse, keyboard and
  mnemonic navigation.
- Closing a menu after a command preserves focus when the command has moved it
  into a newly opened dialog. Commands that do not choose a new target still
  restore the focus held before menu navigation.

The bundle desktop keeps one managed window per opened HELP bundle and one per
Markdown document. `F6`/`Shift-F6`, Window List, Tile and Cascade all operate
on the same `TVDialogManager` stack. Dynamic windows use distinct persisted
geometry keys, so moving or maximizing one does not overwrite another.
Tile and Cascade place resizable windows through that same resizer, updating
the restored geometry and zoom glyph together.
HELP Contents activates a selected `TVOutline` node directly through its
`TVEvent` handler; it does not click a rendered anchor. The HELP window retains
its outline and each HELP/Docs window retains its scrollbars for redraw and
destruction, while DOM references are used only for binding and rendering.
Window List is a normal `TVListBox`: empty/normal rows use the dialog list cyan
palette and its focused row uses the original green/white focused colors.
Markdown documentation uses a dedicated Editor palette: blue background with
yellow base text. These two colors stay fixed across themes and Viewer palette
customization; headings, links and syntax accents may use their own colors.

### TVScrollBar

Custom scrollbar for `[data-tv-scroll-frame]` containers. Handles thumb drag, track clicks, arrow buttons, wheel events.

- `refresh()` — Re-observe replaced viewport content and redraw both axes.
- `setActive(active)` — Enable input for the active window or make both axes
  non-interactive without changing their Turbo Vision scrollbar palette.
- `destroy()` — Stop repeat/drag state and detach element/global listeners and
  the `ResizeObserver`.

### Theme Engine

- `initializeTVTheme()` — Shared shell/bundle startup, including stored theme
  and palette restoration
- `applyThemePreset(preset)` — Apply "light", "dark", or "auto" theme
- `applyColorPalette(palette)` — Apply custom color palette from `DOS_COLORS`
- `setColorPaletteAttribute(palette, index, attr)` — Update every Color-dialog
  view that references the same 1-based `cpAppColor` index
- `readStoredThemePreset()` / `readStoredColorPalette()` — Read from localStorage

The default color source is the exact 135-entry Turbo Vision 2.0
`cpAppColor`. `COLOR_GROUPS` does not own duplicate colors: Viewer and Puzzle,
for example, both reference indexes 8–14. CSS first resolves an owner palette
for a window/dialog and then derives its current active, passive or dragging
frame state. Common list and scrollbar controls inherit from that owner.

### Utility Functions

- `measureCells()` — Returns `{width, height}` of a monospace character cell
- `fillBorders()` — Measures cells and fills `data-tv-border-fill` / `data-tv-border-side` elements

## tv-dialogs.js

Standard application dialogs.

Dialog client areas are composed from shared TVision JS widgets. About,
Widget Gallery, Open a File, Change Directory, ASCII Table,
Calculator, Calendar, Colors, MIDI Player, Find and Search assemble labels,
inputs, buttons, status text, lists/outlines, clusters and History controls as
`TVGroup` children rather than handwritten dialog-specific HTML. Dynamic
content is owned by concrete controls such as `TVAsciiTable`,
`TVCalendarView`, `TVColorSelector`, `TVColorDisplay` and the shared list
classes. `TVRect` bounds emitted by `TVView` are authoritative for window,
dialog and control position and size. CSS is limited to palette presentation,
the intrinsic browser structure of shared primitives (for example a list's
scrollbar column or a button's two-row face), and the internal cells of a
specialised game surface. It must not repeat outer dialog/control dimensions.
ASCII Chart, Calculator, Colors, History, MIDI, Window List and the game
windows follow this rule; their concrete geometry is declared in JS.
Open a File derives its two-column grid row count from `TVFileList.rows` and
keeps arrow/Page navigation in `keyDestination()` on the shared
`TVListViewer.handleEvent()` path. The MIDI display marks its five owned text
views by semantic part so its palette does not depend on child order.
The MIDI playlist is a `TVListBox` containing ready and cloud-marked pending
items, with the cloud at the row's right edge. Its Filter is a `TVLabel` linked
to a `TVInputLine`; input broadcasts
filter game and track text. A single playlist click switches playback;
arrow-key navigation changes selection without starting audio, while Enter
plays the selected row. Choosing a pending item stops the previous track,
queues the download through the server and uses the existing progress-dialog/
gauge views for download progress.
After the initial list render, `TVListViewer` updates only the old and new
selection rows instead of revisiting the full catalog on every click.
`TVListBox` resolves a row from the event target first; geometry scanning is
only a fallback when the target is outside a row.
The Filter uses the shared `TVHistory`/`TVHistoryWindow` popup; selecting a
stored filter updates the list without starting a track.
The MIDI `TVBarGauge` dispatches its click through `TVEvent` to seek in the
active sequence. Its total MIDI tick count comes from `parseMidiFile()`, since
FluidSynth can report zero total ticks immediately after starting playback.
The shared `TVScrollBar` handles arrow, track and thumb pointer input for both
axes. A track click calculates its target from the axis's track element and
scrolls the owned viewport directly.
`TVImage` binds its drawn root like other shared views, so
`setImage()` updates the visible game cover.
Under More, a shared `TVCheckBoxes` control selects sequential (default) or
random next-track playback. The audio engine remains inside `TVMidiSynth`, but
uses FluidSynth with a General MIDI SoundFont instead of per-note oscillators;
the dialog still owns the transport commands and reacts to completion. The
SoundFont fetch starts when the player opens, before the first track click. Pause
stops the active FluidSynth player without clearing its position, and Play
resumes the same sequence; Stop resets it. Adjacent transport buttons are
separated by one text cell. The dialog reports one aggregate playback event
when a track ends or is stopped, accumulating only active play time across
Pause/Play cycles.

The shared `TVHelpViewer`/`TVHelpWindow`, THelpViewer's own UHF loading and the
generated-page `TVContextHelpWindow` live in `tv-context-help.js`; they are not
part of the standard-dialog module. The viewer converts clicks on topic,
contents, index and context-help links to a `help-link` `TVEvent`; the owning
window handles or delegates navigation. Actual target file/topic/line data
remains on rendered links because it is required to resolve external files.

The shared `TVDialog` frame supplies a clipped client viewport between its two
vertical frame sides. Backdrop clicks become a close command in
`TVDialog.handleEvent()`, sharing the normal dialog command path. A bounded
top-level `TVGroup` is positioned relative to
that client viewport, and nested groups with bounded children preserve their
absolute `TVRect` coordinates. Dynamic `changeBounds()` operations therefore
resize content without moving controls into the title, footer or outside the
frame.

is no password field or tokenless public registration.

and only the list that owns keyboard focus uses the focused-row attribute.
The selectors support arrow-key navigation in

## tv-screensaver.js

### TVScreenSaver

`TVView`-derived full-screen saver with a browser overlay as its drawing
surface. Browser mouse and keyboard input is forwarded as `TVEvent` to
`handleEvent()`; stopping restores the previously focused control. The idle
trigger is installed in the page/bundle application and defaults to five
minutes. This follows DOS Navigator's `TSSaver` / `TProgram.GetEvent` owner
and event model, while keeping browser timers and DOM drawing at the adapter
boundary.

- `start()` — Start the selected saver instance and preserve current focus
- `stop()` — Dismiss, detach resize handling and restore focus (also triggered by mouse or keyboard input)
- `TVScreenSaver.installIdleStart()` — Install the shared five-minute idle trigger once per page

Both the generated-page shell and bundle application install the same idle
trigger when the screen-saver asset is available. If that optional asset fails
to load, both applications continue without idle or menu-launched savers.
Active modes remeasure and reinitialize after a browser resize.

Mode descriptions:
- **stars** — Falling star characters with random colors
- **bounce** — Bouncing "THelpViewer" text, color changes on wall bounce
- **clock** — Big ASCII-art clock with date
- **matrix** — Matrix-style falling green character streams
- **projector** — Moving transparent text-cell aperture over a dark screen;
  adapted from DOS Navigator's `TProjector`. The browser reveals the live page,
  whereas the DOS version reveals a saved text-mode screen buffer.

[DOS Navigator 1.51 `IDLERS.PAS`](https://github.com/maximmasiutin/Dos-Navigator/blob/master/IDLERS.PAS)
also includes blank, radial-star and moving-clock savers; its
[`DNAPP.PAS`](https://github.com/maximmasiutin/Dos-Navigator/blob/master/DNAPP.PAS)
can launch external saver programs. Our current `stars` and `clock` modes are
not exact ports of those originals. Projector is credited to RIT Research
Labs: “Based on Dos Navigator by RIT Research Labs.”

Constants: `SAVER_FPS = 15`, `SAVER_STAR_COUNT = 60`

### Server Statistics

`TVStatisticsDialog` derives from `TVDialog`. Its client area is composed from
`TVGroup`, `TVStaticText`, two `TVListBox` objects and standard `TVButton`
controls: categories are on the left, ranked values on the right, and OK plus
Refresh are at the bottom. The right list uses a horizontal `TVScrollBar` when
a topic or other value exceeds its width. The classic gray dialog palette is
inherited from `TVDialog`, while both lists retain the standard colored list
palette. It reads
`/api/statistics/summary` and shows total/daily visits, HELP/Docs/topic opens,

show their HTTP/network cause, while client rendering failures are labeled
separately.

### Server Terminal

`TVServerTerminalDialog` is assembled from shared `TVDialog`, `TVTerminal`,
`TVInputLine`, `TVLabel`, `TVStaticText` and `TVButton` objects. Its black output
area follows an explicitly launched server-side job. The browser can only
attach to an existing job using its 12-character ID and random access key;
it cannot start a command. The key is shown as a password input and is never
stored by the browser. Output is fetched incrementally, while line input is
sent only while the job reports `running`; controls lock when it exits.

Launch from the server (or inside Docker) with:

```bash
python -m thelpviewer.server.terminal --label "Example" -- python -u -c "print(input('Name: '))"
docker compose exec viewer python -m thelpviewer.server.terminal --label "Example" -- python -u -c "print(input('Name: '))"
```

Paste the printed ID and access key into System → Server Terminal. Keep the
launcher running until its command finishes. Jobs, output and input queues live
under `THELP_STATE_DIR/terminal/`; the state file stores only a hash of the
key. The terminal API has no process-creation route. Treat output and keys as
sensitive: use HTTPS when exposing the viewer outside localhost, and do not
run commands that reveal secrets to other viewers of the server console.

The existing `TVDialogManager` supplies the registered name, active target and
open/close lifecycle for both dialogs and windows. `TVBundleApp` accumulates
visible active intervals from that shared state; `TVDialog` and `TVWindow` do
not contain HTTP or statistics code. Games are recognized through the shared
`TVGameDialog` base rather than a second name list.
DOS Prompt uses the same managed-window lifecycle as a `tool`, counting opens
and bucketed tool duration without recording DOS commands. Its runnable
predicate excludes initialization and explicit Pause as well as the shared
inactive/hidden exclusions. The Statistics dialog exposes **Tool time**.

HELP counters use the catalog's long display name. The technical source
filename is accepted only as a compatibility fallback for clients that do not
send that display name.

FastAPI stores only daily aggregate counters in SQLite. The store uses the
rollback journal rather than WAL so it remains usable through Docker Desktop
bind mounts. Country is accepted only from deployment-proxy country headers;
IP addresses, cookies, persistent
visitor identifiers and raw user-agent/referrer strings are never persisted.
Search terms, exact durations and exact performance values are likewise never
stored. Page-exit delivery uses `sendBeacon()` with a keepalive request as a
fallback; unsupported performance observers simply omit that metric.
`GET/POST /api/hall-of-fame/{game}` stores the public player name, score and
short note, keeps only the correctly ordered top ten, and reports whether a
submitted score qualified.

### System Information

`TVSystemInformationDialog` is a standard gray `TVDialog` composed from two
`TVListBox` controls, static text and OK/Refresh buttons. It reports application
metadata, browser and OS, display and character-cell geometry, locale, storage
availability and supported browser capabilities. Its Server section reads
`/healthz`, `/helps/catalog.json` and `/docs/catalog.json` to show the running
version and catalog sizes. Opening the dialog does not submit any of the
displayed values to the statistics endpoint.

Entry point. Called via `TV.initTurboVision()`.

- `start()` — Initializes theme, chrome, shared desktop/widgets and layout
- `initTheme()` — Reads stored theme from localStorage, applies it
- `initChrome()` — Initializes menu bar and status line
- `initLayout()` — Delegates border/background, clock and resize ownership to
  `TVDesktop.startLayout()`.
- `initShellWidgets()` — Creates `TVDesktop`, initializes scrollbars and
  resizers, registers dialogs and sets up the five-minute idle screen saver.

### TurboVisionWindowResizer

- Draggable title bar (move), resize handle (bottom-right corner)
- `maximize()`, `restore()`, `toggle()`/`toggleMaximize()`; `TVWindow.zoom()`
  uses this shared resizer when one is bound, including HELP and Docs windows
- Persists geometry to localStorage per optional `data-tv-window-storage-key`
- `destroy()` persists the final geometry and detaches drag, handle and
  `beforeunload` listeners.

### TVAppContext

Reads configuration from `data-tv-*` body attributes:
- `helpHref`, `indexHref`, `pageKind`, `statusHint`, `topicContext`, `topicHref`

## tv-bundle-app.js

Single-page application for browsing help file bundles.

### Classes

| Class | Purpose |
|-------|---------|
| `TVLoadingDialog` | DOS Navigator-style `TVBarGauge` and `TVPercentGauge` during bundle download |
| `BundleWindowManager` | Multi-window help file viewer with cascade/tile |
| `TVBundleApp` | Main bundle application |

### TVBundleApp

- Implements application commands in `handleEvent()`. `TVMenuView` converts
  menu selection into `evCommand`; the browser adapter only translates DOM
  input into menu `TVEvent` records. File, Search, Window, theme, screen-saver
  and context-help actions are not separate menu click handlers.
- `start()` — Loads catalog, handles URL params, shows welcome
- `_loadCatalog()` — Fetches `helps/catalog.json` and `docs/catalog.json`
- `_openDocWindow(filename, markdown)` — Opens rendered Markdown in a doc window (z-index 5, above help windows but below menu bar)
- `_registerDialog(name, factory)` — Creates and registers a dialog with the dialog manager
- Registered dialogs include About, File Open, Change Directory, Find, topic
  Search, the utility dialogs and all twelve games including Tron and Hanoi.
- Find targets the currently active HELP or Docs window through `TVEditor`;
  HELP viewports receive a lifecycle-managed read-only adapter only when first
  searched.

The Help Files menu uses `product_name`, `version`, and `menu_name` from
`helps/catalog.json` to render product → version → file. Entries without
`product_name` are shown as direct Help Files items.

The public Docs catalog and static site export omit internal files named
`* Audit.md` or `* RE Notes.md`. Markdown links are resolved inside the viewer;
repository-relative `docs/...` links in the root README are translated to the
public Docs root instead of opening a broken `docs/docs/...` URL. Other
same-origin links are checked by the active `TVBundleApp` before navigation;
a missing target opens the existing `TVMessageBox` without reloading the
desktop or spawning another viewer tab. Direct invalid browser URLs retain the
server-side fallback.

### BundleWindowManager

- `showIndex()` — Display bundle index (topic list)
- `showTopic(bundle, contextHex)` — Display a specific topic
- `showContents(bundle)` — Display hierarchical contents through `TVOutline`
- `goBack()` — Navigate history
- `tile()`, `cascade()` — Arrange open windows
- `closeAll()` — Close all open help windows

### renderMarkdown(md)

Minimal Markdown-to-HTML converter.

Supported syntax: headings (`# H1` through `###### H6`), bold (`**text**`), italic (`*text*`), inline code, links, unordered/ordered lists, horizontal rules, fenced code blocks, tables (`| col | col |`).

### URL Parameters

- `?file=<name>` — Auto-load a help bundle by catalog name
- `?topic=<hex>` — Navigate directly to a topic (requires `?file=`)
- `?search=<query>` — Open search dialog with pre-filled query
- `?docs=<file.md>` — Open a documentation Markdown file

### Z-Index Hierarchy

The viewer uses a fixed z-index stack for layering:

| Layer | z-index | Element |
|-------|---------|---------|
| Desktop pattern | 0 | Background |
| Help windows | 1 | `tv-window` |
| Doc windows | 5 | Markdown document viewer |
| Dialog overlays | 10 | `TVDialog` overlays |
| Menu bar | 10 | `.tv-menu-bar` (position: relative) |
| Menu popups | 20 | Dropdown menu panels |
| Submenus | 25 | Nested submenu panels |
| Modal overlay | 9999 | Loading dialog |

### Browser regression tests

`tests/test_browser_smoke.py` exercises the viewer in Chrome. The Safari
close/history regression is opt-in: enable **Safari → Settings → Developer →
Allow remote automation**, then run
`THELP_SAFARI_TEST=1 .venv/bin/python -m pytest -q tests/test_safari_smoke.py`.
The test starts its own local server and uses macOS `safaridriver`; it is
skipped by default on machines without this browser configuration.

### Data Format

Bundle JSON structure:
```json
{
  "window": { "cols": 80, "rows": 24, ... },
  "header_label": "...",
  "index_label": "...",
  "index_entries": [{ "context_hex": "0001", "title": "..." }, ...],
  "topics": [{ "context_hex": "0001", "title": "...", "html": "...", "text": "..." }, ...],
  "search_index": ["term1", "term2", ...],
  "source_name": "TURBO.TPH"
}
```
